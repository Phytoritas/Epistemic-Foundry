# Epistemic Foundry v4.0.0 — Evolution-Governed Hypothesis Validation Architecture

**Status:** `SPEC_BUNDLE` / `REFERENCE_BLUEPRINT`  
**Implementation:** not claimed  
**Production readiness:** not claimed

Epistemic Foundry v4 turns the v3 evidence-governed research plugin into an
**evolution-governed hypothesis discovery and validation architecture**. It
adopts the strongest reusable ideas from ShinkaEvolve—population search,
lineage, islands, archives, model routing, novelty filtering, asynchronous
evaluation, and agent skills—without allowing an evolving generator or
evaluator to become the authority for evidence, hidden holdouts, policy, or
promotion.

## v4 constitutional split

```text
Evolution Chamber  = proposes, mutates, crosses, challenges and prioritizes
Verifier Firewall  = qualifies immutable evaluators and hidden/OOD tests
Foundry Kernel     = owns state, policy, capabilities, effects and replay
Noetic Ledger      = owns provenance, receipts and audit history
Evidence Parliament = adjudicates evidence under deterministic hard gates
```

Novelty is not truth. Fitness is not evidence. A surviving candidate is not a
validated hypothesis. High promotion requires source-grounded evidence,
search-scope receipts, dependency correction, qualified evaluation,
adaptive-search statistics, adversarial challenge, and independent
replication where required.
