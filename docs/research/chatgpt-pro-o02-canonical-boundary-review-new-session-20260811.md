DECISION: AUTHORIZED_LOCAL_REPAIR
NUMBER_RULE: Treat `bool` as a JSON literal; otherwise accept only `type(n) is int` when conversion to finite binary64 succeeds losslessly (`int(float(n)) == n`), or `type(n) is float` when finite; reject all numeric subclasses and NaN/±Infinity, then serialize the resulting binary64 value using RFC 8785 ECMAScript `Number::toString` rules, including `-0.0` as `0`. ([RFC Editor][1])
BLOCKER: Fact 4 is incompatible with default Python integer decoding: the accepted value `2**68` JCS-serializes as `295147905179352830000`, but default `json.loads` materializes that token as a non-binary64-exact Python `int`, causing strict re-sealing to reject valid canonical bytes. The smallest repair is to parse every sealed numeric token into finite binary64 first, normalize integral values to `int` only afterward when needed, and then JCS-reseal and exact-compare. ([RFC Editor][1])
RATIONALE: The frozen schema already selects the canonical byte algorithm, and O02 owns the implementation directory; no stated higher authority requires a shared API first. An internal conforming serializer is therefore an in-scope repair, while changing shared hashing ownership is not. Rejecting lossy caller integers preserves fail-closed bindings, and the decoder repair preserves valid JCS self-round-trips.
