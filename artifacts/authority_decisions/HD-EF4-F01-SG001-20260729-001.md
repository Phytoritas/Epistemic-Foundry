## Identity, retry, replay, and override

`classification_hash` is the SHA-256 of an RFC 8785 JCS-equivalent canonical
preimage containing exactly the schema ID, request ID and immutable input hash,
classifier version, PolicyBundle hash, normalized accepted signals, ordered
reasons and risk factors, exact projection, and nullable superseded
classification and HumanDecision hashes. Self-identifying and volatile fields
are excluded. `classification_id` is `EWC-` plus the lowercase digest.
`classified_at` is assigned once by the durable ClassificationCommitter in UTC
with millisecond precision and is reused on retry.

The idempotency key binds request ID, request input hash, classifier version,
and PolicyBundle hash. Equal key and equal preimage returns the existing
artifact, receipt, ID, hash, and timestamp. Equal key and unequal preimage fails
`IDEMPOTENCY_CONFLICT`. Strict replay requires complete identity or fails
`REPLAY_DIVERGENCE`.

Corrections never mutate a classification. A HumanDecision may create a new
same-revision classification only when it raises class or protection; the new
artifact includes the prior and HumanDecision hashes, receives a new receipt,
records `SUPERSEDES`, and advances the active pointer by compare-and-swap. A
lower classification requires a new request revision or PolicyBundle.
